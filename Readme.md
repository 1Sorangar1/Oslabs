Лаба 2, вариант 13
Сценарий 2:
Локальный сетевой чат. Хост и клиенты - участники чата. Хост может как сам отправлять личные и общие сообщения в чат, так и передавать сообщения от других участников в общий чат или лично. Общие сообщения отображаются в чате (консоли) у всех подключенных участников, личные сообщения отображаются в чате только у отправителя и адресата. Если клиент не отправляет сообщения больше минуты и не является хостом, то ему отправляется SIGKILL для завершения. Сообщения в чате появляются в порядке времени их отправления.

Конфигурация: Родственные. Один к одному.
Каждый хост запускает ровно одного клиента. Синхронизация локальным семафором

Типы взаимодействия: 4,6,7.
4.Очереди сообщений (mq_open). TYPE_CODE - mq. Работа с очередью должна производиться в каждом процессе уже после создания дочернего (так, будто это несвязанные процессы).
6.Именованные каналы (mkfifo). TYPE_CODE - fifo. Работа с именованным каналом должна производиться в каждом процессе уже после создания дочернего (так, будто это несвязанные процессы). После окончания работы родительский процесс должен удалять файл именованного канала.
7.Сокеты (socket). TYPE_CODE – sock

Запуск проекта:


chmod +x build.sh
./build.sh
./build/host_mq
./build/host_fifo
./build/host_sock


Управление чатом:


Хост:
Вводите сообщения для отправки всем клиентам
Для личного сообщения клиенту: @client <сообщение>
Для выхода: /quit

Клиент:
Вводите сообщения для отправки хосту
Для личного сообщения хосту: @host <сообщение>
Для выхода: /quit


Ключевые компоненты:

main.cpp - Основная программа, реализующая сценарий "Один к одному":
Автоматически определяет тип соединения по имени исполняемого файла
Создает хост-процесс, который форкает клиентский процесс
Реализует двустороннюю связь через выбранный механизм IPC

conn.h / conn.cpp - Абстрактный базовый класс соединения:
Определяет интерфейс Conn с методами Read() и Write()
Содержит структуру ChatMessage для единообразного формата сообщений

Конкретные реализации соединений:
ConnMQ (conn_mq.h/cpp) - Очереди сообщений POSIX
ConnFIFO (conn_fifo.h/cpp) - Именованные каналы (FIFO)
ConnSock (conn_sock.h/cpp) - Сокеты домена UNIX

conn_factory.h/cpp - Фабрика соединений:
Создает экземпляры соединений нужного типа
Позволяет легко добавлять новые типы соединений

logger.h/cpp - Система логирования:
Записывает логи в файл chat.log
Отображает логи в консоль
Потокобезопасна благодаря мьютексам


Взаимодействие процессов:
Сценарий "Один к одному" (родственные процессы):

Хост создает соединения (FIFO, MQ или сокеты) как создатель
Хост форкает процесс-клиент
Клиент открывает существующие соединения

Устанавливается двусторонняя связь:
Хост → Клиент: для отправки сообщений клиенту
Клиент → Хост: для получения сообщений от клиента

Синхронизация:
Используются именованные семафоры POSIX для каждого соединения
Чтение: семафор sem_read (начальное значение 0)
Запись: семафор sem_write (начальное значение 1)
Гарантирует отсутствие race conditions


Таймауты клиента:
Клиент отслеживает время последнего отправленного сообщения
Если прошло 60 секунд без отправки сообщений, клиент завершается
Перед завершением отправляет хосту уведомление


Структура сообщения:
struct ChatMessage {
    int32_t type;        // 0 - общее, 1 - личное, -1 - служебное
    int32_t sender_id;   // ID отправителя
    int32_t receiver_id; // ID получателя (для личных сообщений)
    int64_t timestamp;   // Время отправки (миллисекунды с эпохи)
    char text[256];      // Текст сообщения
};


Типы сообщений:
type = 0: Общее сообщение для всех
type = 1: Личное сообщение конкретному участнику
type = -1: Служебное сообщение (присоединение, готовность, выход)


Особенности реализации:

Очереди сообщений (Message Queue):
Использует mq_open(), mq_send(), mq_receive()
Сообщения сохраняются системой, если получатель не готов

Именованные каналы (FIFO):
Использует mkfifo(), open(), read(), write()
Родительский процесс удаляет файлы FIFO после завершения

Сокеты (Socket):
Использует socket(), bind(), listen(), accept()
